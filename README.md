# Лабораторная работа № 3. Связи между таблицами

Вариант 7 — «Военнослужащий».

## Цель работы

Разработать веб-приложение для учёта военнослужащих с использованием Spring Data JPA и не менее трёх связанных таблиц. Реализовать отображение и добавление данных, поиск минимум по трём комбинациям критериев и проверку всех входных данных.

## Архитектура проекта

- **Стек:** Java 25, Spring Boot 4.1.1, Maven, Spring MVC, Spring Data JPA, Hibernate ORM, Bean Validation, Thymeleaf, HTML и CSS.
- **СУБД:** H2 в режиме in-memory (`jdbc:h2:mem:lb3`). Hibernate создаёт таблицы при запуске с помощью `spring.jpa.hibernate.ddl-auto=create-drop`; добавленные данные не сохраняются между перезапусками приложения.
- **Основные слои:**
  - **Model:** сущности `Serviceman`, `Address` и `MilitaryRank`, описывающие таблицы и связи между ними.
  - **DTO:** классы `ServicemanForm`, `AddressForm`, `RankForm` и `SearchForm` для приёма и валидации данных форм и поисковых параметров.
  - **Controller:** `ServicemanController` обрабатывает просмотр, поиск и добавление военнослужащих; `RankController` — просмотр и добавление званий. Контроллеры проверяют результаты валидации и передают данные в HTML-шаблоны.
  - **Service:** `ServicemanService` подготавливает условия поиска, преобразует DTO в сущности и сохраняет военнослужащего вместе с адресом в одной транзакции.
  - **Repository:** интерфейсы `ServicemanRepository` и `MilitaryRankRepository`, наследующие `JpaRepository`. Используются методы `save()`, `findAll()`, `findById()` и `existsById()`, а также собственные методы `search()` и `existsByNameIgnoreCase()`.
  - **View:** Thymeleaf-шаблоны `servicemen/list.html`, `servicemen/form.html` и `ranks.html`. Оформление хранится в `static/css/style.css`.

**Сущности и связи:**

| Сущность | Таблица | Содержание |
|---|---|---|
| `Serviceman` | `servicemen` | Фамилия, имя, отчество, национальность, дата рождения, должность и ссылки на адрес и звание |
| `Address` | `addresses` | Почтовый индекс, страна, область, район, город, улица, дом и квартира |
| `MilitaryRank` | `military_ranks` | Название звания и обратная коллекция военнослужащих |

- `Serviceman → Address`: связь **один к одному**, внешний ключ `address_id`. Для каждого военнослужащего создаётся собственная адресная запись. Каскад `CascadeType.PERSIST` позволяет сохранять новый адрес вместе с военнослужащим.
- `Serviceman → MilitaryRank`: связь **многие к одному**, внешний ключ `rank_id`. Несколько военнослужащих могут иметь одно звание из справочника.
- `MilitaryRank → Serviceman`: обратная сторона связи **один ко многим**, заданная через `mappedBy = "rank"`. Дополнительная таблица связи не создаётся.
- Идентификаторы генерируются базой данных и не отображаются в списках как отдельные столбцы.

**Endpoints:**

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/` | Перенаправление на список военнослужащих |

## Алгоритм работы

1. **Запуск и инициализация базы.** `Lb3Application` запускает Spring Boot. Hibernate создаёт таблицы `servicemen`, `addresses` и `military_ranks`. После создания таблиц выполняется `data.sql`, добавляющий звания «рядовой», «сержант», «лейтенант» и «капитан». Военнослужащие добавляются пользователем.
2. **Отображение списка.** При переходе на `/` браузер перенаправляется на `/servicemen`. Контроллер принимает поисковые параметры в `SearchForm`, проверяет их и получает записи через сервис и репозиторий. Без заполненных фильтров отображаются все военнослужащие.
3. **Загрузка связанных данных.** JPQL-запрос использует `join fetch` для адреса и звания. Шаблон получает необходимые связанные данные до формирования HTML; настройка `spring.jpa.open-in-view=false` отключает продление JPA-контекста на время отображения страницы.
4. **Поиск и отбор.** Пользователь заполняет нужные фильтры и отправляет GET-форму. Пустые условия не ограничивают выборку, а заполненные объединяются через `AND`. Результаты сортируются по фамилии, имени и идентификатору.

   | Комбинация | Пример отбора |
   |---|---|
   | Фамилия + национальность | Фамилия содержит «иван», национальность — «русский» |
   | Город + звание | Город содержит «моск», звание — «капитан» |
   | Должность + звание | Должность содержит «команд», звание — «лейтенант» |

   Текстовые сравнения выполняются без учёта регистра. Фамилия, город и должность ищутся по вхождению части строки, национальность — по полному совпадению, звание — по ID. Допускается одновременное применение большего числа фильтров. Символы `%` и `_` экранируются, чтобы пользовательский ввод воспринимался буквально в условиях `LIKE`.

5. **Открытие формы создания.** При GET-запросе `/servicemen/new` контроллер передаёт в шаблон пустой `ServicemanForm` и список званий. Пользователь вводит личные данные и полный адрес, а звание выбирает из справочника.
6. **Проверка входных данных.** После POST-запроса `/servicemen` Spring связывает разрешённые поля с DTO и запускает Bean Validation. Проверяются заполненность строк, максимальная длина, корректность преобразования даты, дата рождения в прошлом и положительный ID звания. Вложенный `AddressForm` проверяется через `@Valid`. Дополнительно контроллер проверяет существование выбранного звания в базе.
7. **Обработка ошибок.** Ошибки преобразования и валидации поступают в `BindingResult`. При их наличии данные не сохраняются: возвращается форма с введёнными значениями, списком званий и сообщениями рядом с ошибочными полями. При ошибках поисковых параметров запрос поиска не выполняется, на странице показываются ошибки и пустой список результатов.
8. **Сохранение военнослужащего.** Сервис загружает выбранное звание, удаляет крайние пробелы из строк, создаёт `Address` и `Serviceman` и устанавливает связи. Вызов `save()` сохраняет военнослужащего и новый адрес в одной транзакции. После успешного сохранения браузер перенаправляется на список — используется схема Post/Redirect/Get.
9. **Добавление звания.** На `/ranks` пользователь вводит название. Контроллер проверяет заполненность, длину и отсутствие такого названия без учёта регистра. При ошибке возвращается та же страница; при успехе звание сохраняется и становится доступным в формах выбора.
10. **Отображение результата.** Thymeleaf формирует строки списка через `th:each`, выводит значения через `th:text`, связывает поля формы через `th:field` и показывает ошибки через `th:errors`. Дата рождения отображается в формате `dd.MM.yyyy`.
